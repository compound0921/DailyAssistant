# 发布与更新

检查更新读取 GitHub Releases 的 latest，用 `tag_name` 与安装包内的版本号比较。只做手动检查，不在启动时请求网络。

## 版本号

- `pubspec.yaml` 的 `version: 1.0.1+2`：前半是 versionName，`+2` 是 Android versionCode。
- 每次发版同时递增两者，tag 使用 `v1.0.1`。
- 比较时忽略 tag 的 `v` 前缀和 `+build` 构建号。

## 构建安装包

Android：

```bash
flutter build apk --release
```

产物为 `build/app/outputs/flutter-apk/app-release.apk`，重命名为 `DailyAssistant-1.0.1-android.apk`。

Windows（需要安装 Inno Setup 6）：

```bash
flutter build windows --release
iscc /DMyAppVersion=1.0.1 installer\daily_assistant.iss
```

产物为 `build/installer/DailyAssistant-1.0.1-windows-setup.exe`。

## 发布

1. 在 GitHub 创建 Release，tag 写 `v1.0.1`。
2. 上传两个资产，保持命名：
   - `DailyAssistant-1.0.1-android.apk`
   - `DailyAssistant-1.0.1-windows-setup.exe`
3. 更新说明写进 Release 正文，应用内会原样展示。
4. 不要勾选 prerelease；检查更新只读取 latest。

## 注意

- Android 覆盖安装要求新旧 APK 使用同一签名。当前 release 仍用 debug 签名；换成正式签名后，旧版本无法覆盖安装，卸载会清空本地数据。切换签名前先备份数据，或约定从某个版本起重装。
- `versionCode` 必须递增，否则 Android 拒绝安装低版本。
- 未登录 GitHub API 每小时 60 次，手动检查足够；超限时应用提示稍后再试。
- Windows 安装器默认装到当前用户目录，无需管理员；运行时会关闭正在运行的旧版本。
- 资产地址只接受 `github.com` / `githubusercontent.com` 的 https 链接。缺少对应平台资产时，应用提供“打开下载页”。
